# Правила работы над Soundline

Файл описывает **процесс**, по которому мы ведём разработку. Продуктовые решения и
план — в [`roadmap.md`](./roadmap.md) и [`docs/specification.md`](./docs/specification.md).

## Рабочий цикл (итерации)

Работаем строго по одной итерации из `roadmap.md` за раз.

1. **Итерация.** Агент выполняет ровно одну итерацию из `roadmap.md`.
2. **Стоп на ревью.** Агент останавливается и показывает результат. **Коммит не делается.**
3. **Ревью.** Пользователь смотрит результат.
4. **ОК → коммит.** Только после явного одобрения агент коммитит.
5. **Пауза.** Агент **не приступает к следующей итерации**, пока пользователь явно об этом
   не попросит.

Жёсткие правила:

- Не начинать следующую итерацию без явной команды пользователя.
- Не коммитить до одобрения. После одобрения — один коммит на итерацию.
- Не забегать вперёд: не делать работу будущих итераций. Минимально необходимое (заглушка
  модуля, чтобы сборка/тесты оставались зелёными) допустимо, но это отмечается в отчёте.
- В конце итерации `pnpm typecheck`, `pnpm test`, `pnpm build` должны быть зелёными.
- Обновлять в `roadmap.md` чекбоксы задач и статус (`· ✅ готово`) той же итерации — в рамках
  этой же итерации.

## Коммиты

- Один коммит на итерацию, только с её содержанием.
- Сообщение: `type(scope): суть (iteration N)`, например `feat(core): domain model (iteration 1)`.
- Мелкие типы: `feat`, `fix`, `chore`, `docs`, `test`, `refactor`, `ci`.
- Артефакты сборки (`dist/`, `node_modules/`) и локальные снимки не коммитятся — см. `.gitignore`.

## Конвенции

- **Пакеты:** `@nickkupriyanov/soundline-core`, `@nickkupriyanov/soundline-react`.
- **Префиксы:** классы `sn-*`, CSS-токены `--sn-*`, атрибуты `data-sn-*`.
- **Core без React и DOM.** Логика/состояние/производная модель живут в core; DOM — только
  через подпуть `soundline-core/dom` и только внутри функций (без обращений к `window`/
  `document` при импорте).
- **Ничего не происходит при создании контроллера.** Побочные эффекты — в `start()`/`stop()`,
  оба идемпотентны. Воспроизведение и данные инъектируются (`engine`, `adapter`).
- **Доступность — часть определения готовности**, а не отдельная полировка.
- **Изменение публикуемого пакета** сопровождается changeset (до `1.0.0` несовместимое
  изменение — `minor` с миграцией).
- Форматирование — Prettier (`pnpm format`), стиль как в `booking`.

## Definition of done для итерации

1. `pnpm typecheck && pnpm test && pnpm build` зелёные.
2. Новый публичный контракт задокументирован JSDoc; для React — есть запускаемый пример
   (playground/Storybook добавляются с Iteration 14).
3. Логика core покрыта тестами core; поведение и доступность обвязки — тестами обвязки.
4. Статус задачи в `roadmap.md` обновлён.

## Область видимости

- Работаем только в `soundline/`.
- `booking/` — референс стиля и практик, только для чтения. Другие соседние папки не трогаем
  и не читаем.
